# KJB Reader → Mac App Store via GitHub Actions (no Mac needed)

This repo now contains everything to build and submit the Safari version of
KJB Reader from GitHub's free macOS runners. The workflow
`.github/workflows/safari-release.yml` runs `./build.sh safari`, converts the
package to an Xcode project, signs it with your Apple certificates, exports a
Mac App Store .pkg, and can upload it straight to App Store Connect.

One-time setup takes about 45–60 minutes. After that, each new release is one
button click.

---

## Prerequisites

- **Apple Developer Program membership** (USD 99/year) — developer.apple.com
- **A GitHub account** (the workflow uses free public runners; private repos
  also get free macOS minutes)

## Step 1 — Create a GitHub repository with this code

1. On github.com: New repository → e.g. `kjb-reader`.
2. Upload this folder's contents to the repo root (manifest.json must sit at
   the repo root; if you keep the extension in a subfolder instead, adjust the
   `./build.sh safari` path in the workflow).
3. In the repo: Settings → Actions → General → Workflow permissions →
   **Read and write**.

## Step 2 — Create your signing certificates (no Mac required)

On any computer with OpenSSL (Windows via WSL/Git Bash, Linux, or ask your
agent):

```bash
# 1. Private key + certificate request
openssl req -newkey rsa:2048 -nodes \
  -keyout apple_key.pem -out request.certSigningRequest \
  -subj "/emailAddress=you@example.com/CN=KJB Reader/C=SG"

# 2. After EACH certificate below: download the .cer and pack it with the key
openssl x509 -inform der -in certificate.cer -out certificate.pem
openssl pkcs12 -export -out distribution.p12 \
  -inkey apple_key.pem -in certificate.pem
```

On [developer.apple.com](https://developer.apple.com/account/resources/certificates/list):

| Portal action | Certificate type |
|---|---|
| Create a Certificate → upload `request.certSigningRequest` | **Apple Distribution** |
| Create a Certificate → upload the same request again | **Mac Installer Distribution** |

(If the portal rejects a second cert on the same CSR, regenerate the CSR and
repeat — both types are required: the first signs the app, the second signs
the .pkg installer.)

Then base64-encode both .p12 files (choose any password when packing):

```bash
base64 -w0 distribution.p12    # copy the output
base64 -w0 installer.p12
```

## Step 3 — Create App IDs and provisioning profiles

On the portal → Identifiers:

1. Create `com.kingjamesbiblereader.kjbreader` (App).
2. Create `com.kingjamesbiblereader.kjbreader.Extension` (App) — the Safari
   extension target generated by the converter.

On the portal → Profiles:

1. + → Distribution → **Mac App Store** → select the main App ID → select
   your Apple Distribution certificate → download
   `KJBReader.provisionprofile`.
2. Repeat for the `.Extension` App ID → download
   `KJBReaderExtension.provisionprofile`.
3. Base64 both: `base64 -w0 KJBReader.provisionprofile`

## Step 4 — Create the App Store Connect record + API key

1. [App Store Connect](https://appstoreconnect.apple.com) → My Apps →
   **+ New App** → Platform: macOS → Name: KJB Reader → Bundle ID: the one
   from Step 3 → create. (The app record must exist before uploading.)
2. App Store Connect → Users and Access → Integrations/Keys →
   **+ App Store Connect API** → role: **App Manager** → download the
   `.p8` key → note the **Key ID** and **Issuer ID**.
3. Base64 the key: `base64 -w0 AuthKey_XXXXXXXXXX.p8`

## Step 5 — Add the GitHub repository secrets

Repo → Settings → Secrets and variables → Actions → New repository secret:

| Secret name | Value |
|---|---|
| `MAC_APP_CERTIFICATE_P12` | base64 of the Apple Distribution .p12 |
| `MAC_APP_CERTIFICATE_PASSWORD` | the .p12 password you chose |
| `MAC_INSTALLER_CERTIFICATE_P12` | base64 of the Mac Installer .p12 |
| `MAC_INSTALLER_CERTIFICATE_PASSWORD` | that .p12 password |
| `MAC_PROVISIONING_PROFILE` | base64 of `KJBReader.provisionprofile` |
| `MAC_EXTENSION_PROVISIONING_PROFILE` | base64 of the extension profile |
| `APPLE_TEAM_ID` | your 10-character Team ID (portal Membership page) |
| `ASC_KEY_ID` | App Store Connect API Key ID |
| `ASC_ISSUER_ID` | App Store Connect Issuer ID |
| `ASC_KEY_P8` | base64 of the .p8 key |
| `KEYCHAIN_PASSWORD` | any password (runner-internal, throwaway) |

## Step 6 — Run it

Repo → Actions → **Safari Release (Mac App Store)** → Run workflow:

- First run: leave "Upload" **off** — this validates everything and produces
  a downloadable .pkg artifact without touching App Store Connect.
- When the build is green, run again with "Upload" **on**. The build appears
  in App Store Connect under KJB Reader → TestFlight/macos build.
- Each upload needs a unique build number — the workflow handles it with the
  run number; override via the input if you retry.

Then finish the listing in App Store Connect (screenshots from your existing
promo set, privacy policy: https://kingjamesbiblereader.com/privacy) and
submit for review.

## Troubleshooting

- **"No signing certificate ... found"** — the .p12 secrets are wrong or the
  cert type isn't Apple Distribution. Re-check Step 2.
- **Export fails on teamID** — `APPLE_TEAM_ID` secret must be the 10-char
  Team ID, not your name.
- **altool upload rejected** — the ASC app record (Step 4.1) must exist and
  the bundle ID must match exactly.
- **First run hiccups are normal** — runner-based signing is exacting; send
  the failing log to your agent and it can be tuned. Once green, it stays
  green.

## Local Safari build (cross-platform, no Mac)

`./build.sh safari` — produces `build/kjb-reader-safari-v0.4.252.zip`, the
same package the workflow converts. The Safari patches (no sidePanel
permission, popup toolbar action, isSafari background logic) live in
`scripts/make_safari.py` and fail loudly if background.js is refactored
without updating them.
